Peta API

Web Blade memakai session/cookie dan merender HTML. API v1 memakai bearer token Sanctum, menerima request JSON, dan mengembalikan response JSON melalui API Resource. Identitas token harus dikirim kembali pada setiap request protected.

POST /api/v1/auth/login
  -> Sanctum membuat bearer token
GET /api/v1/courses + Authorization: Bearer <token>
  -> auth:sanctum memverifikasi token
  -> controller memfilter data menurut role
  -> API Resource memilih field whitelist
  -> JSON: data + links + meta

Base URL lokal: http://127.0.0.1:8000/api/v1. Sertakan header Accept: application/json, terutama saat menguji validasi dan error.

Checkpoint 1 — Mengapa model mentah berbahaya?

Jawaban

Model mentah dapat menserialisasi banyak kolom database. Daftar hitam seperti $hidden hanya melindungi field yang diingat developer; kolom sensitif baru dapat bocor jika tidak dimasukkan ke daftar tersebut. API Resource adalah whitelist: hanya field yang ditulis di toArray() yang dikirim.

Jawaban lisan: “Saya tidak mengembalikan model mentah karena kolom baru bisa ikut terserialisasi tanpa sengaja. Saya memakai API Resource agar response menjadi whitelist dan hanya berisi field yang memang dibutuhkan client.”

Contoh kode

// Jangan lakukan:
return response()->json(User::all());

// Gunakan Resource:
return new UserResource($request->user());

Lokasi kode

app/Http/Controllers/Api/AuthController.php — response login dan /me

Demonstrasi

  1. Buka UserResource::toArray() dan tunjukkan field yang keluar.
  2. Tunjukkan bahwa password dan remember_token tidak ada dalam array return.
  3. Jalankan php artisan test --filter=test_login_returns_sanctum_token_and_whitelisted_user.

Checkpoint 2 — Apa beda 401 dan 403?

Jawaban

401 Unauthorized berarti request belum memberikan identitas yang valid, misalnya token tidak ada atau token salah. 403 Forbidden berarti identitas valid sudah diketahui, tetapi pengguna tidak memiliki izin terhadap resource atau tindakan tersebut.

Jawaban lisan: “401 itu identitas belum terbukti; 403 itu identitas sudah diketahui, tetapi tindakannya tidak diizinkan. Di API saya, request course tanpa token mendapat 401, sedangkan mahasiswa yang mencoba membuat assignment mendapat 403.”

Contoh kode

// Semua endpoint data berada di balik autentikasi token:
Route::middleware(['auth:sanctum', 'throttle:60,1'])->group(function () {
    Route::post('/courses/{course}/assignments', [AssignmentController::class, 'store']);
});

// AssignmentController::authorizeCourseManage()
abort_unless($allowed, 403);

Lokasi kode

routes/api.php — group auth:sanctum
app/Http/Controllers/Api/AssignmentController.php — authorizeCourseManage()
tests/Feature/WeekSixApiFeatureTest.php — test_api_course_list_requires_authentication() dan test_student_cannot_create_assignment()

Demonstrasi

401 tanpa token:

curl.exe -i -H "Accept: application/json" http://127.0.0.1:8000/api/v1/courses

Login demo untuk mendapat token:

$login = Invoke-RestMethod -Method Post `
  -Uri http://127.0.0.1:8000/api/v1/auth/login `
  -Headers @{ Accept = 'application/json' } `
  -ContentType 'application/json' `
  -Body (@{ email = 'mahasiswa@kampuslms.test'; password = 'password'; device_name = 'checkpoint' } | ConvertTo-Json)
$token = $login.token

403 mahasiswa mencoba membuat assignment pada course yang dapat dibacanya:

$courses = Invoke-RestMethod -Uri http://127.0.0.1:8000/api/v1/courses -Headers @{ Authorization = "Bearer $token"; Accept = 'application/json' }
$courseId = $courses.data[0].id
$body = @{ title = 'Tes'; instructions = 'Tes otorisasi'; due_at = '2030-01-01T00:00:00Z' } | ConvertTo-Json
Invoke-WebRequest -Method Post -Uri "http://127.0.0.1:8000/api/v1/courses/$courseId/assignments" -Headers @{ Authorization = "Bearer $token"; Accept = 'application/json' } -ContentType 'application/json' -Body $body

Checkpoint 3 — Mengaktifkan API routes di Laravel 12

Jawaban

Pada skeleton Laravel 12, routes/api.php tidak selalu dibuat otomatis. Perintah php artisan install:api memasang scaffolding API, Sanctum, konfigurasi token, dan migration token. bootstrap/app.php perlu memuat file route API agar endpoint terdaftar dengan prefix /api; route proyek menambahkan versi /v1.

Jawaban lisan: “Saya mengaktifkan API dengan php artisan install:api. Di Laravel 12, bootstrap aplikasi menentukan file route yang dimuat. File API kemudian menerima prefix /api, dan grup versi proyek menambahkan /v1.”

Contoh kode

// bootstrap/app.php
->withRouting(
    web: __DIR__.'/../routes/web.php',
    api: __DIR__.'/../routes/api.php',
    commands: __DIR__.'/../routes/console.php',
    health: '/up',
)

// routes/api.php
Route::prefix('v1')->group(function () {
    Route::post('/auth/login', [AuthController::class, 'login']);
});

Checkpoint 4 — Apa fungsi whenLoaded()?

Jawaban

whenLoaded() memasukkan relasi hanya jika controller sudah melakukan eager load. Ini mencegah Resource memicu lazy loading tersembunyi untuk setiap item. Tanpa eager load, relasi tidak disertakan oleh Resource; bila kode malah mengakses relasi langsung pada setiap baris, query dapat membengkak menjadi N+1.

Jawaban lisan: “whenLoaded menjaga Resource tidak memaksa query relasi. Controller menentukan kapan relasi diambil, biasanya dengan with(). Jadi query list terkontrol dan tidak satu query tambahan per course.”

Contoh kode

// app/Http/Controllers/Api/CourseController.php
$query->with('lecturer')->withCount(['materials', 'assignments']);

// app/Http/Resources/CourseResource.php
'lecturer' => $this->whenLoaded(
    'lecturer', fn () => new UserResource($this->lecturer)
),
'counts' => [
    'materials' => $this->whenCounted('materials'),
    'assignments' => $this->whenCounted('assignments'),
],

Lokasi kode

app/Http/Controllers/Api/CourseController.php — index() dan show()
app/Http/Resources/CourseResource.php — whenLoaded() dan whenCounted()
app/Http/Controllers/Api/AssignmentController.php — index() memakai with('creator')
app/Http/Resources/AssignmentResource.php — creator hanya disertakan saat dimuat

Demonstrasi

  1. Buka endpoint daftar course dan tunjukkan query eager load.
  2. Buka CourseResource dan jelaskan kapan lecturer/count tersedia.
  3. Jalankan php artisan test --filter=test_api_resource_returns_only_public_course_fields.
  4. Untuk latihan BREAK, hapus sementara with('lecturer'), jalankan request, dan amati field lecturer tidak dikirim karena whenLoaded(). Pulihkan barisnya setelah demo.

Checkpoint 5 — Kenapa pesan gagal login harus sama?

Jawaban

Jika API menjawab “email tidak ditemukan” untuk satu kasus dan “password salah” untuk kasus lain, pihak luar dapat menguji apakah sebuah email terdaftar. Ini disebut user enumeration. Gunakan pesan generik untuk kedua kegagalan.

Jawaban lisan: “Pesan error login saya tidak membedakan email dan password supaya response tidak menjadi alat untuk menebak akun yang terdaftar. Detail teknisnya tetap dicatat di sisi server, bukan dibuka ke client.”

Contoh kode

if (! $user || ! Hash::check($credentials['password'], $user->password)) {
    throw ValidationException::withMessages([
        'email' => ['Email atau kata sandi salah.'],
    ]);
}

Lokasi kode

app/Http/Controllers/Api/AuthController.php — login()
tests/Feature/WeekSixApiFeatureTest.php — test_login_does_not_reveal_whether_email_exists()

Demonstrasi

  1. Jalankan php artisan test --filter=test_login_does_not_reveal_whether_email_exists.
  2. Tunjukkan test mengirim email yang ada dengan password salah dan email yang tidak ada.
  3. Keduanya menghasilkan 422 dan isi errors.email yang sama.

Checkpoint 6 — Kenapa login wajib di-throttle?

Jawaban

Tanpa rate limit, penyerang dapat mengirim percobaan password berulang dengan cepat. API ini membatasi login menjadi 5 request per menit; endpoint protected lain dibatasi 60 request per menit. Saat batas login terlampaui, Laravel mengembalikan 429 Too Many Requests.

Jawaban lisan: “Login saya throttle 5 per menit untuk memperlambat brute force. Endpoint API ber-token memakai 60 per menit agar penggunaan normal tetap lancar. Nilai ini kebijakan awal proyek dan dapat disesuaikan berdasarkan pemantauan.”

Contoh kode

// routes/api.php
Route::post('/auth/login', [AuthController::class, 'login'])
    ->middleware('throttle:5,1');

Route::middleware(['auth:sanctum', 'throttle:60,1'])->group(function () {
    // endpoint API protected
});

Lokasi kode

routes/api.php — throttle login dan group protected
tests/Feature/WeekSixApiFeatureTest.php — test_login_is_limited_to_five_attempts_per_minute()

Demonstrasi

  1. Jalankan php artisan test --filter=test_login_is_limited_to_five_attempts_per_minute.
  2. Test melakukan lima percobaan gagal lalu memastikan percobaan keenam mendapatkan 429.
  3. Tunjukkan middleware throttle di route API. Jangan melakukan stress test ke server publik.
