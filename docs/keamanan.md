# Tabel Titik Rawan IDOR

IDOR (Insecure Direct Object Reference) terjadi ketika pengguna dapat mengganti ID
resource pada URL/request dan membaca atau mengubah resource milik pihak lain.
Tabel ini mencatat endpoint yang menerima ID model dan kontrol server-side yang
melindunginya. Pembatasan tampilan di Blade bukan kontrol keamanan; keputusan
akses dilakukan oleh middleware, Policy, query, dan pemeriksaan pasangan parent-child.
Kolom **Test** memetakan setiap baris ke feature test yang benar-benar memeriksa
perilaku tersebut.

## Batas cakupan

- Route Web untuk course, material, assignment, submission, grade, dan enrollment
  memakai autentikasi. Route di prefix admin juga dibatasi middleware role admin;
  route dosen dan mahasiswa dibatasi role masing-masing.
- Endpoint API berada di middleware `auth:sanctum`. API menyediakan course,
  material (hanya baca), dan assignment. Submission dan grade hanya tersedia
  melalui route Web; tidak ada endpoint API untuk keduanya.
- Perlindungan setiap fitur baru harus diterapkan di server-side controller/query;
  menyembunyikan tombol dengan Blade saja tidak mencegah request langsung.
- Setiap baris tabel di atas dipetakan ke feature test yang berjalan dengan
  `RefreshDatabase`, factory, dan assertion status HTTP/database. Jalankan
  `php artisan test` untuk memverifikasi seluruh suite.
- CI pada `.github/workflows/ci.yml` menjalankan `php artisan test` setelah
  menyiapkan `.env`, dependency Composer, Node 22, aset Vite, dan migrasi.

## Menjalankan pengujian otorisasi

Seluruh feature test dan unit test:

```bash
php artisan test
```

Test yang paling langsung memetakan tabel ini:

```powershell
php artisan test tests/Feature/AdminCourseCrudFeatureTest.php tests/Feature/MaterialAuthorizationFeatureTest.php tests/Feature/SubmissionAuthorizationFeatureTest.php tests/Feature/GradeAuthorizationFeatureTest.php
```

Test CRUD dan kebijakan yang sudah ada:

```bash
php artisan test --filter=WeekSevenCrudFeatureTest
php artisan test --filter=ModelPoliciesTest
```

Untuk pengujian manual terhadap lingkungan demo, jalankan aplikasi dan pastikan
akun demo serta data course sudah di-seed, lalu dari Git Bash jalankan
`scripts/test-authz.sh`. Skrip login dengan tiga akun demo, menguji status HTTP
untuk course dan assignment, lalu menghapus course sementara yang dibuatnya.
Default URL adalah `http://127.0.0.1:8000`; atur `BASE_URL` jika server berjalan
di alamat lain. Pastikan `curl` dan PHP CLI tersedia di PATH atau atur `PHP_BIN`
ke executable PHP Laragon. Skrip ini bersifat mutatif; jangan menjalankannya pada
production tanpa persetujuan dan cadangan data.
